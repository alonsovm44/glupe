# Glupe v6.2 Roadmap: Enterprise Grade

Version 6.2 focuses on transforming Glupe from a powerful prototype into a production-ready, enterprise-grade toolchain. The key themes are **security, performance, deterministic verification, and IDE integration**.

---

## 1. Security: Execution Sandboxing (Zero-Trust AI)

*   **Feature:** Introduce a `--sandbox` flag.
*   **Description:** All AI-generated code, build scripts (`make`, `cmake`), and binaries executed via `-run` will be run inside an ephemeral, isolated environment (e.g., Docker container or a WASM runtime).
*   **Goal:** Eliminate the security risk of running unverified AI-generated code directly on a host machine or CI runner. This is critical for enterprise adoption.

## 2. Performance: Parallel Container Generation

*   **Feature:** AST-Driven Concurrency for `-series` and `-make` modes.
*   **Description:** The compiler will use the **Global Symbol Graph** to perform a Topological Sort on all semantic containers. Containers that do not share dependencies will be generated concurrently by spawning asynchronous threads for LLM API calls.
*   **Goal:** Drastically reduce build times for large projects, transforming multi-minute builds into sub-minute builds.

## 3. Verification: Automated Test-Driven Generation (TDG)

*   **Feature:** Introduce a `--strict-tests` flag.
*   **Description:** For each container, Glupe will secretly generate a corresponding unit test based on the container's intent. It will compile both the code and the test. If the test fails, the assertion error is fed back into the self-healing loop. The AI's output is not accepted until the tests pass.
*   **Goal:** Move beyond syntax-level validation (compiler errors) to logical validation, ensuring the generated code is not just correct, but *functionally* correct.

## 4. IDE Integration: Language Server Protocol (LSP)

*   **Feature:** Create a `glupe-lsp` binary.
*   **Description:** Extract the core parsing (`parser.hpp`) and analysis (`processor.hpp`) logic into a standard Language Server Protocol implementation.
*   **Goal:** Provide rich, real-time diagnostics directly in IDEs like VS Code. This includes showing red squiggly lines for prompt arithmetic contradictions and providing hover-previews for cached container content.

## 5. Automation: Automated Dependency Management

*   **Feature:** Automatic resolution of third-party dependencies.
*   **Description:** When the AST parser detects a missing external dependency (e.g., `#include <curl/curl.h>`), it will use the LLM to identify the required package and auto-generate the appropriate package manager command (`vcpkg install curl`, `pip install requests`, etc.) or inject it into the project's `CMakeLists.txt` or `package.json`.
*   **Goal:** Further reduce manual intervention during the build process.

## 6. Robustness: Formal Type Constraints on Containers

*   **Feature:** Allow native language signatures to wrap semantic containers.
*   **Description:** Developers can define a container with a rigid, typed interface, leaving only the implementation body to the AI.
    ```cpp
    // Glupe enforces that the LLM MUST return an int and accept a std::string
    int process_data(const std::string& input) $${
        parse the json string and return the user_id
    }$$
    ```
*   **Goal:** Address the "No formal semantics" limitation by providing a way to enforce strict type contracts on AI-generated logic.

## 7. CI/CD: Native Pipeline Annotations

*   **Feature:** Add a `--format=[github-actions|gitlab]` flag to the `audit` command.
*   **Description:** Instead of just printing a markdown report, Glupe will emit platform-specific workflow commands (e.g., `::error file=main.cpp,line=14::Missing retry logic`).
*   **Goal:** Allow CI platforms to place inline comments directly on Pull Requests, pinpointing exactly which semantic container violated the architectural specification.
