# Glupe Lexer Specification Documentation

## Overview
This document provides a comprehensive overview of the lexer specification for the Glupe programming language. The lexer, written using Flex, defines the tokenization rules for Glupe's syntax, including variables, containers, and raw code handling. It integrates with Bison for parsing and utilizes the `ast.hpp` file for Abstract Syntax Tree (AST) node definitions.

## Purpose
The lexer's primary purpose is to convert the Glupe source code into a stream of tokens that the parser (generated by Bison) can process. It handles various syntactic elements, such as variables, containers, raw code, and comments, while ensuring proper state transitions for different language constructs.

## Key Components

### 1. **Initial State (`<INITIAL>`)**
   - **String Literals**: Matches single-quoted (`'...'`), double-quoted (`"..."`), and backtick-enclosed (``...``) strings, treating them as raw code.
   - **Comments**: Handles single-line (`//`, `#`) and multi-line (`/* ... */`) comments, also treated as raw code.
   - **Variable Definitions**: Detects variable start tokens (`$$:`, `$CONST:`, `$:`) and transitions to the `VAR_ID` state.
   - **Container Definitions**: Detects container start tokens (`$$`, `$`) and transitions to `BLOCK_HEADER` or `INLINE_HEADER` states.
   - **Raw Code**: Matches any sequence of characters not part of the above rules, treating them as raw code.

### 2. **Variable Identifier State (`<VAR_ID>`)**
   - **Whitespace**: Skips spaces and tabs.
   - **Identifier**: Matches valid variable names (`[a-zA-Z_][a-zA-Z0-9_]*`) and transitions to the `VAR_VALUE` state.

### 3. **Variable Value State (`<VAR_VALUE>`)**
   - **Value Content**: Captures the variable value until a newline is encountered, optionally handling the `->` operator.
   - **Newline**: Transitions back to the initial state upon encountering a newline.

### 4. **Block/Inline Header States (`<BLOCK_HEADER>`, `<INLINE_HEADER>`)**
   - **Whitespace**: Skips spaces, tabs, and newlines.
   - **Keywords**: Matches keywords like `ABSTRACT`, `->`, and operators (`+`, `-`, `*`, `/`, `^`).
   - **Identifiers and Literals**: Matches identifiers, numbers, and string literals.
   - **Braces**: Detects `{` to transition to the intent states (`BLOCK_INTENT` or `INLINE_INTENT`).

### 5. **Intent States (`<BLOCK_INTENT>`, `<INLINE_INTENT>`)**
   - **End Tokens**: Detects `}$$` or `}$` to transition back to the initial state.
   - **Intent Text**: Captures the intent text within the container definition.

## Usage
The lexer is designed to be used in conjunction with a Bison-generated parser. It processes Glupe source code, tokenizes it according to the rules defined above, and passes the tokens to the parser for further processing. The lexer ensures proper state management to handle different syntactic constructs accurately.

## Behavior
- **State Transitions**: The lexer uses exclusive states (`%x`) to cleanly separate the lexing of different constructs, such as variables and containers.
- **Token Handling**: Tokens are created dynamically (`yylval.str = new std::string(yytext)`) and returned with their corresponding token type.
- **Error Handling**: Implicitly handled by Flex's default behavior for unrecognized characters.

## Integration with AST
The lexer integrates with the `ast.hpp` file, which defines the AST nodes (`RawCodeNode`, `VariableNode`, `ContainerNode`, `ProgramNode`). The parser uses these nodes to construct the AST based on the tokens generated by the lexer.

## Example
Given the input:
```glupe
$$ MyContainer -> Parent { This is the intent } $$
$: var = "value"
```
The lexer would produce tokens corresponding to:
- `T_BLOCK_START`, `T_IDENTIFIER`, `T_ARROW`, `T_IDENTIFIER`, `T_LBRACE`, `T_INTENT_TEXT`, `T_BLOCK_END`
- `T_EPHEMERAL_VAR_START`, `T_IDENTIFIER`, `T_VAR_VALUE`
